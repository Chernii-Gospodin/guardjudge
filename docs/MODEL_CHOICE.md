# GuardJudge: выбор модели для лёгкого LLM-гардрейла (LLM-as-a-Judge)

*Сценарий 1 проекта. Черновик текста для Google Doc.*

## 1. Задача

Нужна отдельная компактная языковая модель-«судья». Она получает фрагмент из определённой точки
пайплайна LLM-приложения и возвращает вердикт:

| стадия | что проверяется |
|---|---|
| `input` | сообщение пользователя (jailbreak, prompt injection, вредный запрос) |
| `tool_call` | вызов инструмента перед выполнением (опасные аргументы, эксфильтрация) |
| `rag` | документ из базы знаний перед попаданием в контекст (непрямая инъекция) |
| `output` | ответ модели перед отправкой пользователю (вредный контент, утечки) |

Формат ответа строгий: `{"verdict": "safe|unsafe", "category": "<категория>"}`.
Категории: `jailbreak`, `prompt_injection`, `harmful_content`, `data_exfiltration`, `tool_abuse`, `rag_poisoning`.

Требования к модели:

1. **Лёгкость.** Судья вызывается на каждой стадии, поэтому задержка и стоимость умножаются на число проверок.
2. **Полное дообучение на доступном железе** (Colab/Kaggle T4, 16 ГБ, без bf16). Сценарий 2 проекта уже использует LoRA, здесь сознательно обучаются все веса.
3. **Многоязычность, включая русский.** В командном датасете есть русскоязычные атаки.
4. **Открытая лицензия**, чтобы модель можно было распространять как продукт безопасности.
5. **Поддержка в экосистеме**: HF Transformers, vLLM, Ollama.

## 2. Сколько памяти нужно для полного дообучения

При полном дообучении с AdamW в fp32 на каждый параметр уходит около 16 байт:
4 байта веса, 4 байта градиенты, 8 байт состояние оптимизатора. Активации добавляются сверху
и уменьшаются через gradient checkpointing.

| модель | параметры | ~память без активаций | влезает в T4 16 ГБ |
|---|---|---|---|
| SmolLM2-360M-Instruct | 0.36B | ~5.8 ГБ | да |
| Qwen2.5-0.5B-Instruct | 0.49B | ~7.9 ГБ | да |
| **Qwen3-0.6B** | 0.6B | ~9.6 ГБ | **да** |
| Llama-3.2-1B-Instruct | 1.24B | ~20 ГБ | нет |
| Qwen3-1.7B | 1.7B | ~27 ГБ | нет |
| Phi-3-mini (3.8B), Llama-3-8B | 3.8B / 8B | 61 / 128 ГБ | нет (только LoRA/QLoRA) |

Модели из описания проекта (Phi-3, Llama-3-8B) на T4 можно дообучить только через LoRA/QLoRA.
Это задача сценария 2. Для полного дообучения в сценарии 1 реалистичен класс моделей до ~0.6B.

## 3. Кандидаты

| модель | лицензия | плюсы | минусы |
|---|---|---|---|
| **Qwen3-0.6B** | Apache 2.0 | новейшее семейство Qwen, 119 языков (включая русский), контекст 32k; на этом же бэкбоне построен готовый гардрейл Qwen3Guard-Gen-0.6B | гибридный «thinking»-режим: в шаблоне нужно отключать `enable_thinking` |
| Qwen2.5-0.5B-Instruct | Apache 2.0 | самая лёгкая из многоязычных, простой chat template | старее и слабее Qwen3 |
| SmolLM2-135M/360M | Apache 2.0 | очень быстрая | ориентирована на английский, мала для тонкой классификации |
| Llama-3.2-1B-Instruct | Llama 3.2 Community License | сильная модель класса 1B | полное дообучение не влезает в T4; русский официально не поддерживается; лицензия ограничительнее |
| Gemma-3-1B-it | Gemma Terms of Use | хорошее качество для размера | не влезает в T4 для полного дообучения; собственная лицензия |
| Llama Guard 3 1B / Qwen3Guard-Gen-0.6B | Llama / Apache 2.0 | уже обучены как гардрейлы | фиксированная таксономия и формат ответа, нет стадий `tool_call`/`rag`; используем как **baseline** |

## 4. Выбор: Qwen3-0.6B, полное дообучение

1. **Укладывается в бюджет.** Около 9.6 ГБ на состояние обучения плюс активации с gradient checkpointing: обучение на T4 в fp16 со смешанной точностью.
2. **Многоязычность.** Русский поддерживается из коробки, это важно для русскоязычных инъекций из датасета.
3. **Чистый эксперимент 2×2.** Qwen3Guard-Gen-0.6B — гардрейл от разработчиков Qwen на том же бэкбоне. Поэтому обе модели дообучаются одинаково и сравниваются до и после:

   | | до | после полного дообучения |
   |---|---|---|
   | Qwen3-0.6B (универсальные веса) | zero-shot с нашим промптом | GuardJudge-Qwen3 |
   | Qwen3Guard-Gen-0.6B (веса, уже обученные на безопасность) | родной формат `Safety: ...` | GuardJudge-Qwen3Guard |

   Данные, промпт (общий ChatML-шаблон, побайтово одинаковый), гиперпараметры и размер у моделей совпадают.
   Поэтому разница «до/после» показывает эффект дообучения, а разница между строками — пользу от
   стартовых весов, уже обученных на безопасность.
4. **Лицензия Apache 2.0** разрешает распространять дообученную модель.
5. **Экосистема.** Модель поддерживают Transformers, vLLM и Ollama. Дообученный чекпоинт — обычная HF-модель, слияние адаптеров не нужно.

Запасной вариант — **Qwen2.5-0.5B-Instruct**: меняется одной строкой `model_name` в конфиге.

## 5. Методология дообучения

- **Формат:** SFT «промпт судьи → JSON-вердикт». Loss считается только по токенам вердикта, промпт маскируется.
- **Один промпт для обучения и инференса:** системная инструкция, стадия, описание стадии, необязательный контекст и проверяемый фрагмент. Всё рендерится chat template модели (`enable_thinking=false`).
- **Гиперпараметры (стартовые):** lr 1e-5 (полное дообучение требует LR на порядок ниже, чем LoRA), cosine, warmup 3%, эффективный батч 16, 2 эпохи, max_length 1024, weight decay 0.01, fp16 AMP, gradient checkpointing, group_by_length. Лучший чекпоинт выбирается по `eval_loss` на валидации.
- **Данные:** командный датасет guardrails_dataset (43.5k train / 6.3k val / 5.5k test; источники WildGuard, Aegis, S-Labs, neuralchemy, dmtrdr, deepset; сплиты не пересекаются по `group_id`). Плюс демо-набор для стадий `tool_call` / `rag` / `output`.
- **Метрики:** precision, recall, F1, FPR, доля неразобранных ответов, задержка p50/p95. Считаются в целом и по стадиям, источникам, языкам и категориям атак.

## 6. Первые результаты

Одни и те же 200 случайных примеров из test:

| модель | P | R | F1 | FPR |
|---|---|---|---|---|
| Qwen3-0.6B — до (zero-shot, наш промпт) | 0.917 | 0.110 | 0.196 | 0.010 |
| Qwen3Guard-Gen-0.6B — до (родной формат) | 0.891 | 0.900 | 0.895 | 0.110 |
| Qwen3-0.6B — после full FT | *после обучения в Colab* | | | |
| Qwen3Guard-Gen-0.6B — после full FT | *после обучения в Colab* | | | |

Qwen3-0.6B без дообучения формально соблюдает JSON-формат, но почти всё помечает как safe (recall 11%).
Qwen3Guard уже сильный baseline (F1 0.895), но даёт 11% ложных срабатываний. Есть смысл проверить,
снизит ли дообучение FPR и подтянет ли источники, где Qwen3Guard ошибается.
Финальные цифры на полном test (5.5k) получаются в `notebooks/train_colab.ipynb`.

## 7. Ограничения и дальнейшая работа

- В командном датасете есть только стадия `input`. Для `tool_call`, `rag` и `output` нужна разметка (синтетика и сценарии агентов).
- Структурированные примеры (trusted instruction + untrusted content) почти все unsafe. Есть риск, что модель выучит формат как признак атаки, поэтому нужны безопасные структурированные примеры.
- Можно попробовать Qwen3-1.7B на GPU от 24 ГБ и сравнить с Qwen3-0.6B: где выигрыш в качестве перестаёт окупать рост задержки.
